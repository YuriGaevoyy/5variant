# Ошибки, найденные при отладке и проверке системных компонентов

УП.02, вариант 5, работы 17–19.

В документе собраны **реальные дефекты**, обнаруженные в ходе локальной проверки и устранённые до выпуска, а также типовые отказы системных компонентов с действиями по диагностике. В среде проверки не было сеанса отладчика Visual Studio: доказательства — тесты (`DeliveryService.Tests`, `DeliveryService.UiTests`), живые проверки API и журналы Serilog.

## 1. Найденные дефекты и их исправление

| № | Симптом | Причина | Исправление | Подтверждение |
|---:|---|---|---|---|
| 1 | Содержимое вкладок рабочего окна не отображалось и не находилось в дереве автоматизации | Пользовательский шаблон `TabControl` скрывал создаваемое содержимое от WPF/UIA | Заменён на стандартный `TabControl` с шаблоном `TabItem` нулевой высоты | 8/8 UI-тестов FlaUI, включая навигацию по разделам |
| 2 | Панель поиска и фильтра переполнялась при ширине окна 1024 px | `DockPanel` не переносил элементы при узком окне | `DockPanel` заменён на `WrapPanel` | UI-тест минимального окна 1024×768 проходит, элементы не перекрываются |
| 3 | UI-тест падал на очистке временной папки: файл занят процессом | Serilog держал открытый дескриптор файла, пока тест уже удалял каталог | Завершение процесса перед очисткой + повтор удаления | Стабильные 8/8 прогонов UI-тестов |
| 4 | Импорт CSV отклонял корректную запись: адрес с запятой читался как лишняя колонка | Поле адреса не было заключено в кавычки в проверочных файлах | Модульные и живые тесты используют кавычки; парсер и API сохраняют формат `Name,Phone,Address,Email` | 64/64 теста и 26/26 живых проверок, включая ошибку в строке 3 |
| 5 | Тест ожидал бизнес-ошибку 400, а получал 409 Conflict | Тест передавал устаревшее значение `version` после предыдущего перехода | Тест обновляет `version` перед следующим утверждением | Корректная проверка правил lifecycle и optimistic concurrency |

Все пять дефектов устранены; регресс-проверка: 64/64 модульных и интеграционных тестов, 8/8 UI-тестов, 26/26 живых проверок API, 0 предупреждений Release-сборки.

## 2. Отказы системных компонентов

| Ситуация | Признак | Действие |
|---|---|---|
| Порт занят | `Address already in use`, API не стартует | Освободить порт или указать другой; WPF автоматически выбирает свободный loopback-порт |
| Нет таблицы | `no such table: Shipments` при первом запуске | Применить миграцию `20261123203756_InitialDelivery` к чистой SQLite; сид выполняется автоматически |
| Некорректный сертификат | Ошибка TLS / ValueError при отдельном запуске API | `dotnet dev-certs https --trust`; для WPF достаточно pinning по SHA-256 |
| 401 / 403 | Токен отсутствует/просрочен либо роль не разрешена | Повторный вход; проверить `role` в JWT; для курьера чужой объект — 404 |
| 429 | Превышен лимит 5 попыток входа в минуту | Подождать до окончания fixed-window (1 мин), затем повторить |
| BOM в CSV | Лишние символы в первом заголовке импорта | Допустим UTF-8 с BOM; при сохранении вручную выбирать UTF-8 без BOM |

## 3. Расположение журналов

| Журнал | Путь | Ротация |
|---|---|---|
| Сервер (Serilog) | Папка `logs/api-.log` рядом с исполняемым файлом API (`DeliveryHost.cs:134`) | Ежедневно, хранение 14 дней |
| Клиент (Serilog-подобный writer) | `%LOCALAPPDATA%/DeliveryService/logs/client-yyyy-MM-dd.log` (`DeliveryService.Desktop/ClientLog.cs:10–11,34`) | Ежедневно, файлы старше 14 дней удаляются при старте |
| Результаты проверок | `artifacts/`, `output/`, а также `docs/api-tests.md`, `docs/artifacts.md` | По мере прогонов |

## 4. Вывод

Отладка велась без графического отладчика: каждый дефект воспроизводился тестом или живым запросом, фиксировался в журнале и закрывался повторным прогоном. Такой подход дал те же доказательства устранения, что и пошаговая отладка, и позволяет воспроизвести все пять случаев из раздела 1.
